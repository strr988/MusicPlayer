# Постоянная музыкальная библиотека

Библиотека хранится в `library.sqlite3` внутри `app.getPath('userData')`. Для нового стандартного профиля Windows это `%APPDATA%\mustplay\library.sqlite3`. Если база есть только в профиле предыдущей версии `%APPDATA%\Music Player`, mustplay продолжает работать с этим профилем. Заменять можно весь каталог установки, включая `resources/app` или `resources/app.asar`. Для ручной резервной копии закройте приложение и скопируйте базу из профиля. Удаление профиля удалит библиотеку.

SQLite доступен только в Electron Main через встроенный `node:sqlite` из Node.js 24 в Electron 45.3.0. В дистрибутив входят обычные зависимости приложения и сам Electron. SQLite не требует отдельного `.node`-бинарника, пересборки под ABI Electron или правила `asarUnpack`. [Node.js 24](https://github.com/nodejs/node/blob/v24.22.2/doc/api/sqlite.md) · [Упаковка Electron](https://www.electronjs.org/docs/latest/tutorial/application-distribution)

## Миграции и запись данных

Миграция `0 → 1` создаёт `tracks` для метаданных, `sources` для источников, `local_files` для идентичности локальных файлов и `imported_folders` для канонических путей выбранных папок. В `sources` уникальна пара `(provider, provider_id)`. У локального провайдера `provider_id` — канонический путь. Отдельная таблица источников позволяет добавить провайдера с собственными идентификаторами и привязать несколько источников к одной записи. Связь локального файла с выбранной папкой определяется по вложенности путей, поэтому родительскую и вложенную папки можно импортировать независимо.

Номер схемы хранится в `PRAGMA user_version`. DDL и изменение версии входят в одну транзакцию. При ошибке приложение откатывает миграцию и завершает запуск. Приложение отказывается открывать схему новее поддерживаемой. У предыдущей сборки библиотека была в памяти, поэтому импорт из неё возможен повторным выбором папок.

Миграция `1 → 2` добавляет реакции и историю. Миграция `2 → 3` добавляет одну запись уровня громкости и отключения звука. Перед первым запуском 0.1.1 закройте плеер и сохраните копию базы, если планируете вернуться на 0.1.0. Для 0.1.0 понадобится копия со схемой 2 или отдельный профиль.

Версия 0.2.0 применяет миграцию `3 → 4`. Она добавляет таблицы `playlists`, `playlist_items` и `wave_settings` с исходным режимом «Баланс». Существующие таблицы библиотеки, источников, реакций, истории и громкости сохраняются. Перед обновлением закройте приложение и скопируйте базу, если планируете возвращаться к 0.1.1. Старые выпуски отклоняют схему 4. Для отката используйте резервную копию подходящей схемы или отдельный профиль. В копии будут данные на момент её создания.

Версия 0.3.0 применяет миграцию `4 → 5`. Таблица `playback_session` хранит один снимок очереди и позицию. До применения миграций существующего профиля Main создаёт рядом с базой отдельный файл `library.sqlite3.v<версия>-<UUID>.backup` через SQLite `VACUUM INTO`. Затем проверяет версию схемы и `quick_check` на копии. Ошибка копирования или проверки останавливает обновление до изменения схемы.

Версия 0.6.0 обновляет базу до схемы 8. Миграция `5 → 6` добавляет `mini_player` и `global_shortcuts`. Миграция `6 → 7` очищает устаревшие записи тестовых треков из исчезнувшей папки `Demo audio`. Миграция `7 → 8` добавляет настройку силы пульсации «Моей волны» в `appearance_settings`. До миграции профиля 0.5.0 создаётся копия схемы 5. Её можно открыть в 0.5.0 в отдельном профиле, скопировав под именем `library.sqlite3`.

Миграция `6 → 7` убирает из медиатеки записи известных тестовых треков из исчезнувших каталогов `Music Player <версия>/Demo audio`. Если в такой папке были только демотреки, она исключается из обновления библиотеки. Изменения применяются к базе и очереди. Музыкальные файлы на диске сохраняются.

Миграция `7 → 8` добавляет `appearance_settings` для сохранения силы пульсации «Моей волны». Исходное значение — 100%.

Миграция `8 → 9` добавляет сохранение темы в `appearance_settings`. Исходная тема тёмная. Для возврата к 0.6.0 откройте копию схемы 8 в отдельном профиле.

Миграция `9 → 10` сохраняет масштаб интерфейса и текущий звуковой эффект. По умолчанию используются 100% и оригинальное звучание. Для возврата к сборке со схемой 9 откройте её резервную копию в отдельном профиле.

Миграция `10 → 11` сохраняет диско-режим и независимый переключатель реверберации для каждого звукового пресета. Для существующих профилей обе функции по умолчанию выключены.

Миграция `11 → 12` расширяет список форматов и хранит исключение локальных источников, импортированные курсоры и режим просмотра текста. ID треков, лайки, история, очередь и связи плейлистов сохраняются; перед обновлением создаётся проверенная резервная копия SQLite. Удаление папки отзывает доступ к её аудио по ID, если трек не входит в другую подключённую папку. Повторный импорт сохраняет ID трека и выдаёт новый ID источника.

Если профиль уже использовался экспериментальной сборкой с альтернативной схемой 6 или 7, Player Experience один раз переносит локальные данные в `library-player-experience.sqlite3` в том же профиле. Исходная база открывается для чтения. Переносятся треки MP3/FLAC, импортированные папки, плейлисты, реакции, история, громкость, режим «Моей волны» и локальная часть корректной очереди. Каждая сборка затем хранит изменения в своём файле базы.

Для возврата к 0.2.0 используйте копию схемы 4. Закройте плеер и сохраните текущий каталог профиля целиком. Скопируйте нужный `.backup` под именем `library.sqlite3` в новый профиль и запустите 0.2.0 с `--user-data-dir`, указывающим на этот профиль. Изменения после создания копии хранятся в профиле 0.3.0. Проверка ZIP выполняет это восстановление с исходным EXE 0.2.0 и сравнивает данные таблиц до и после миграции.

Main включает внешние ключи и допускает один экземпляр приложения на профиль. Сканирование собирает результаты до начала транзакции записи. Запись папки, треков, источников и изменений доступности атомарна. Ошибка чтения отдельного файла отражается в отчёте импорта, а остальные прочитанные файлы сохраняются. Ошибка SQLite откатывает всю запись сканирования.

## Идентификация файлов

- Повторный импорт канонического пути сохраняет ID трека. Изменённый или заменённый файл по этому пути после успешного разбора обновляет теги и получает новый ID источника для нового URL воспроизведения. Формат, неподходящий расширению, и ошибки разбора блокируют обновление метаданных.
- При сканировании нового пути перенос сохраняет ID трека, если на том же томе совпадают идентификатор устройства, номер файла, время создания, размер и время изменения. Совпадение должно быть единственным среди сохранённых и просканированных файлов, а прежний путь должен исчезнуть или разрешаться в новый канонический путь. Это покрывает переименование, включая смену регистра, и перенос между папками. Требуется импорт папки назначения.
- Копия, перенос между томами, перенос с одновременным изменением содержимого или неоднозначное совпадение получают новый ID трека при новом пути. Библиотека не объединяет файлы по тегам или содержимому. Совпадение канонического пути имеет приоритет, если прежний путь занят другим файлом.
- Недоступные треки сохраняют ID и теги. Main проверяет сохранённые источники при запуске, при повторном импорте соответствующей папки и при открытии аудио. Для чтения требуется канонический путь и полное совпадение файловой идентичности, включая время изменения состояния файла. Проверка выполняется и по открытому дескриптору. Неподтверждённый источник недоступен через IPC и медиапротокол. После восстановления доступа к тому же файлу проверка может вернуть доступность, а изменённый файл требует успешного повторного импорта.

## Ограничения

Кнопка **Обновить** перечитывает все ранее выбранные папки, включая пустые. Она добавляет новые файлы, обновляет метаданные и отмечает пропавшие источники как недоступные. Если отдельная папка недоступна, остальные сканируются, а ошибка отображается в отчёте. Каталоги и файлы не отслеживаются непрерывно. Длительность проверки при старте и память одного импорта растут с размером каталога. Производительность на большой библиотеке и на сетевых томах пока не измерена.

Проверка идентичности опирается на сведения файловой системы, включая точность временных меток. Полное хеширование аудиофайлов не применяется. Существующий парсер тегов открывает файл по пути между проверками до и после разбора. Выдача аудио идёт по проверенному дескриптору, а уже открытый файл может изменяться внешним процессом.
