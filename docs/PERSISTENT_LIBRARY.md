# Постоянная музыкальная библиотека

Библиотека хранится в `library.sqlite3` внутри `app.getPath('userData')`. Для стандартного профиля Windows это `%APPDATA%\Music Player\library.sqlite3`. Сохраняйте имя приложения и каталог профиля при обновлении. Заменять можно весь каталог установки, включая `resources/app` или `resources/app.asar`. Для ручной резервной копии закройте приложение и скопируйте базу из профиля. Удаление профиля удалит библиотеку.

SQLite доступен только в Electron Main через встроенный `node:sqlite` из Node.js 24 в Electron 45.3.0. В дистрибутив входят обычные зависимости приложения и сам Electron. SQLite не требует отдельного `.node`-бинарника, пересборки под ABI Electron или правила `asarUnpack`. [Node.js 24](https://github.com/nodejs/node/blob/v24.22.2/doc/api/sqlite.md) · [Упаковка Electron](https://www.electronjs.org/docs/latest/tutorial/application-distribution)

## Миграции и запись данных

Миграция `0 → 1` создаёт `tracks` для метаданных, `sources` для источников, `local_files` для идентичности локальных файлов и `imported_folders` для канонических путей выбранных папок. В `sources` уникальна пара `(provider, provider_id)`. У локального провайдера `provider_id` — канонический путь. Отдельная таблица источников позволяет добавить провайдера с собственными идентификаторами и привязать несколько источников к одной записи. Связь локального файла с выбранной папкой определяется по вложенности путей, поэтому родительскую и вложенную папки можно импортировать независимо.

Номер схемы хранится в `PRAGMA user_version`. DDL и изменение версии входят в одну транзакцию. При ошибке приложение откатывает миграцию и завершает запуск. Приложение отказывается открывать схему новее поддерживаемой. У предыдущей сборки библиотека была в памяти, поэтому импорт из неё возможен повторным выбором папок.

Main включает внешние ключи и допускает один экземпляр приложения на профиль. Сканирование собирает результаты до начала транзакции записи. Запись папки, треков, источников и изменений доступности атомарна. Ошибка чтения отдельного файла отражается в отчёте импорта, а остальные прочитанные файлы сохраняются. Ошибка SQLite откатывает всю запись сканирования.

## Идентификация файлов

- Повторный импорт канонического пути сохраняет ID трека. Изменённый или заменённый файл по этому пути после успешного разбора обновляет теги и получает новый ID источника для нового URL воспроизведения. Формат, неподходящий расширению, и ошибки разбора блокируют обновление метаданных.
- При сканировании нового пути перенос сохраняет ID трека, если на том же томе совпадают идентификатор устройства, номер файла, время создания, размер и время изменения. Совпадение должно быть единственным среди сохранённых и просканированных файлов, а прежний путь должен исчезнуть или разрешаться в новый канонический путь. Это покрывает переименование, включая смену регистра, и перенос между папками. Требуется импорт папки назначения.
- Копия, перенос между томами, перенос с одновременным изменением содержимого или неоднозначное совпадение получают новый ID трека при новом пути. Библиотека не объединяет файлы по тегам или содержимому. Совпадение канонического пути имеет приоритет, если прежний путь занят другим файлом.
- Недоступные треки сохраняют ID и теги. Main проверяет сохранённые источники при запуске, при повторном импорте соответствующей папки и при открытии аудио. Для чтения требуется канонический путь и полное совпадение файловой идентичности, включая время изменения состояния файла. Проверка выполняется и по открытому дескриптору. Неподтверждённый источник недоступен через IPC и медиапротокол. После восстановления доступа к тому же файлу проверка может вернуть доступность, а изменённый файл требует успешного повторного импорта.

## Ограничения

Сканирование запускается выбором папки. Каталоги и файлы не отслеживаются непрерывно. Renderer показывает недоступность при попытке воспроизведения. Длительность проверки при старте и память одного импорта растут с размером каталога. Производительность на большой библиотеке и на сетевых томах пока не измерена.

Проверка идентичности опирается на сведения файловой системы, включая точность временных меток. Полное хеширование аудиофайлов не применяется. Существующий парсер тегов открывает файл по пути между проверками до и после разбора. Выдача аудио идёт по проверенному дескриптору, а уже открытый файл может изменяться внешним процессом.
