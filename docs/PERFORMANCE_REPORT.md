# Производительность mustplay 0.4.1

## Методика

Сравнивались production-сборки 0.4.0 (`fc3abe3`) и 0.4.1. Машина с Windows x64 (10.0.26200), AMD Ryzen 7 8845H с Radeon 780M Graphics, 16 логических процессоров, 27,8 ГиБ доступной ОЗУ. Electron 45.3.0, Chromium 156.0.8078.96, встроенный Node.js 24.22.2. Размер рабочей области окна 1280 × 800 CSS px.

Для каждой версии и каждого размера каталога проведено три последовательных прогона. Каждый прогон использовал новый процесс Electron и новый временный профиль. Сначала импортировался один синтетический MP3 с тестовой обложкой. Затем тестовый IPC-обработчик выдавал детерминированный набор DTO. Остальные записи включали кириллицу и латиницу, длинные теги, повторяющихся исполнителей, разные альбомы, отсутствующие метаданные и записи с обложкой и без неё. Записи с обложкой ссылались на один реальный тестовый источник. На диске был только один тестовый аудиофайл на прогон.

- **Первый показ** отсчитывался от повторной загрузки страницы в существующем окне до появления доступной строки и двух `requestAnimationFrame`. Это время открытия интерфейса с подготовленным каталогом.
- **Поиск, сортировка и действия** отсчитывались от программного события на штатном контроле до двух `requestAnimationFrame`. Запрос `северный` находит около трети записей. Сортировка по названию выполнялась после сброса поиска. Очередь строилась запуском первого импортированного трека, затем измерялось её открытие и удаление 80-го ожидающего элемента. Порядок и полномочия настоящего IPC в релизе отдельно проверялись сквозными тестами.
- **Прокрутка** измерялась при 32 последовательных изменениях позиции от верха таблицы примерно до 98-й строки. Замерены интервалы между callback кадра и количество интервалов дольше 33,4 мс. Прогоны охватывают сопоставимый участок первой страницы.
- **Память** снималась через `app.getAppMetrics()` для Main и Renderer после сценария с открытой очередью. Таблица показывает рабочий набор. Исходные JSON также содержат частную память. GPU и вспомогательные процессы в таблицу не входят.
- **React** считался тестовым перехватчиком DevTools для production-сборки. В отдельном интервале 1,4 с зацикленный тестовый трек воспроизводился в стабильном состоянии, без смены трека. Счётчики охватывают обработанные обновления компонентов и коммиты. Наблюдение основано на внутренних данных Fiber и привязано к версии React проекта.

## Изменения и ограничения

- В 0.4.0 создание всех строк одновременно давало рост задержек и памяти Renderer с размером каталога. В 0.4.1 библиотека и очередь рисуют по 100 строк на страницу, сохраняя нативные таблицу, списки и кнопки. Поиск, сортировка и формирование очереди работают с полным набором в памяти. Кнопки страниц доступны с клавиатуры. При переносе элемента через границу страницы очередь следует за ним и переводит фокус на его действие.
- Снимок Main почти одинаков для 0.4.0 и 0.4.1. Схема SQLite, алгоритм рекомендаций, выдача аудио и производственные IPC-операции остались прежними. Обработка частых событий позиции уже была локализована в Timeline, дополнительная оптимизация плеера не потребовалась.
- Результаты относятся к синтетической нагрузке на одной машине. Первичный показ не включает холодный запуск Electron, массовые проверки доступности файлов и чтение большого каталога из SQLite. Контрольные десктопные сценарии отдельно импортируют 120 синтетических файлов и проверяют реальные MP3, FLAC, обложки и SQLite. Они проверяют функциональность. Скорость файлового импорта, SQLite и загрузки тысяч уникальных обложек в этом релизе не замерялась. Программные события и два кадра дают приближение задержки интерфейса. Это не инструментальная метрика задержки физического ввода.

## Повторение

Соберите обе версии с зафиксированным lockfile. Сохраните `out` из `fc3abe3` в отдельной папке. Из рабочего дерева 0.4.1 выполните команды ниже. Путь к базовой сборке задаётся переменной `MUSTPLAY_PROFILE_BUILD`.

```powershell
$env:MUSTPLAY_PROFILE_BUILD = (Resolve-Path .\release\0.4.1-review\baseline-build).Path
$env:MUSTPLAY_PROFILE_OUTPUT = Join-Path (Get-Location) 'release\0.4.1-review\before-final.json'
node scripts/profile-library.mjs
Remove-Item Env:MUSTPLAY_PROFILE_BUILD
$env:MUSTPLAY_PROFILE_OUTPUT = Join-Path (Get-Location) 'release\0.4.1-review\after-final.json'
node scripts/profile-library.mjs
Remove-Item Env:MUSTPLAY_PROFILE_OUTPUT
```

В следующем релизе стоит измерить отдельно холодный запуск с заполненной SQLite, проверку доступности 10 000 путей на SSD и HDD, а также сканирование обложек с уникальными изображениями. Если пользователям нужна непрерывная прокрутка всего каталога, можно сравнить виртуализацию с текущей постраничной навигацией на той же нагрузке, включая Tab, экранный диктор и восстановление фокуса.
