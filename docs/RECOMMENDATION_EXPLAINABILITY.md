# Объяснения «Моей волны»

## Аудит 0.4.1

База сравнения — коммит `b6cbd7a2d48c9f4e13eaebea828ac9efef38cc16`. Движок дедуплицирует доступные записи по ID, сортирует ID и перемешивает их алгоритмом Fisher–Yates с Mulberry32. При равных баллах сохраняется порядок после перемешивания. Второй независимый генератор с seed XOR `0x9e3779b9` даёт одно значение на позицию очереди.

| Слагаемое | Вклад |
| --- | ---: |
| Лайк на композиции | +6 |
| Совпадение исполнителя с любым лайкнутым треком | +2 |
| Совпадение хотя бы одного жанра с любым лайкнутым треком | +1 |
| В истории до момента расчёта нет действительного `started` | +1 |
| Каждое дослушивание за 30 суток, максимум два | +1 |
| Каждый пропуск за 30 суток, максимум два | −4 |

Даже недоступный лайкнутый трек даёт сигналы по сохранённым тегам. Пустые теги пропускаются. Регистр и крайние пробелы игнорируются. Для исполнителей используется нормализация NFC. Учитываются события с конечной датой до или в момент расчёта. Левая граница окна 30 суток включается. Старые начала продолжают определять, слышал ли пользователь запись. Ошибки и короткие окончания не меняют балл.

Для каждой позиции отбрасываются недавние треки. Размер окна — минимум из пяти и числа доступных записей минус один. Начальный порядок определяется последним началом трека, при равном времени учитывается порядок событий. После выбора ID удаляется из оставшихся кандидатов и ставится первым в окне недавних. При пустом пуле возвращается самый давний из оставшихся недавних. Если можно избежать подряд идущих записей предыдущего известного исполнителя, такие повторы исключаются. Трек без исполнителя проходит этот фильтр.

«Знакомое», «Баланс» и «Открытия» ищут лучшую ещё не слышанную композицию с вероятностями 0%, 20% и 80% соответственно. Если поиск пропущен или подходящего трека нет, выбирается первый по баллу. На холодном старте без лайков все треки получают +1 и порядок зависит от seed и ограничения исполнителей. Без доступных записей очередь пуста. При одной доступной записи движок выдаёт одну позицию независимо от режима. Плеер отдельно избегает немедленного автоматического повторения текущего трека.

Плеер использует ручные элементы раньше автоматического расчёта. Перед запросом он ждёт записи событий предыдущей сессии. Main проверяет источники, читает историю и настройки, фиксирует текущее время и выдаёт новый seed. Из очереди плеер берёт первый подходящий результат, исключая уже испробованные при текущем переходе записи и, в обычном режиме, только что игравший трек. Получение списка само по себе не записывает события прослушивания.

## Диагностика 0.5.0

`generateWave` возвращает прежний список ID. `explainWave` проходит те же ветки `rankWave` и возвращает слагаемые, итоговый балл, число оставшихся и прошедших отбор кандидатов, применение фильтров, итоговый способ выбора и результат проверки поиска нового трека. Метаданные расчёта содержат режим, время UTC, окно реакций, длину окна недавних треков, seed и версию `wave-1`. Балл — внутренний приоритет алгоритма.

В группе выбора после всех фильтров фиксируются число равных баллов и способ решения. При одном кандидате объяснение указывает его уникальность. При выборе по новизне сравниваются только ещё не слышанные кандидаты. Число отсеянных по недавности фиксируется до возможного ослабления фильтра. В проверенных сценариях ослабление не требуется. При уникальных ID размер окна изначально меньше числа кандидатов, а с каждой позицией в окно попадает один уже выбранный трек.

Трасса считывает уже полученное случайное значение. Регрессионный снимок `tests/fixtures/wave-0.4.1.json` снят до изменений. Он проверяет три каталога, три seed и все режимы. Дополнительные тесты покрывают фильтры, пустой вход, неполные теги, ограничение окна и ограничение баллов.

Main передаёт диагностический DTO через отдельный именованный `getWaveRecommendations()`. Обработчик проверяет окно, кадр, URL и отсутствие аргументов. `getWaveQueue()` остаётся доступен для получения ID. [Правила IPC Electron](https://www.electronjs.org/docs/latest/tutorial/security#17-validate-the-sender-of-all-ipc-messages).

## Объяснения и история сеанса

Откройте **Почему этот трек?** на странице «Моя волна». Краткое объяснение показывает причину выбора, повлиявшие ограничения и сигналы. **Технические подробности** показывают балл и параметры конкретного расчёта, включая режим на момент выбора. Если плеер пропустил первые позиции при переходе, объяснение дополнительно указывает причину. Например, алгоритм мог выбрать нужный трек вторым после применения разнообразия, а плеер исключил только что игравшую первую позицию.

Renderer хранит до 100 объяснений, привязанных к ID автоматически выбранных позиций очереди. Диагностика исчезает при смене источника очереди, закрытии приложения или вытеснении из окна. Для восстановленной позиции без трассы страница показывает, что диагностика недоступна. Отдельного журнала в SQLite пока нет. В нём пришлось бы различать все предложения, попытку запуска, факт `started` и пользовательский отклик, а также решить сроки хранения. В 0.5.0 сам расчёт ничего не пишет в историю. Позиции ручной очереди и плейлистов определяются по типу записи и не получают объяснения.
