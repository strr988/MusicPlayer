# Реакции и история прослушивания

Схема SQLite `1 → 2` добавляет `track_preferences` и `playback_events` в ту же базу профиля. Миграция транзакционная; существующие треки, источники и их ID сохраняются. Лайк — один ряд на Track ID. Отмена записывает `liked = false`, а не отрицательную оценку. Время UTC назначает Main.

## Правила событий

Каждый выбор трека создаёт UUID сессии. Возобновление после паузы сохраняет сессию. Начало (`started`) записывается при фактическом `playing`, один раз. Рендер React не записывает события. Запросы записи идут последовательно; SQLite дополнительно допускает не более одного начала и одного терминального события на сессию, проверяет принадлежность треку и отклоняет несовместимые переходы. Повтор того же события идемпотентен.

| Действие | Результат |
| --- | --- |
| Следующий, предыдущий, выбор композиции (включая повторный выбор той же) | `skipped`, если текущая сессия уже играла и ещё не завершена; в том числе при переключении с паузы |
| Пауза и возобновление | Без терминального события и без повторного начала |
| Естественный `ended` | `completed`, если активно прослушано не менее 90% длительности; иначе `ended` |
| Перемотка | Не создаёт завершения; достижение конца после короткого прослушивания даёт `ended`, а не `completed` |
| Недоступный источник, ошибка загрузки/декодера или отказ `play()` | `error`; может существовать без `started`; последующее переключение не создаёт пропуск этой сессии |
| Переключение до начала звучания | Без пропуска |
| Закрытие приложения | Уже записанные факты сохраняются; искусственный пропуск/дослушивание не добавляется |

`listenedSeconds` — время активного воспроизведения по монотонным часам Renderer. Пауза, ожидание буфера и перемотка приостанавливают счётчик; скачок позиции не прибавляет секунды. Повторное прослушивание участка прибавляет реальное время. Это оценка работы плеера, а не подтверждение внимания слушателя. В IPC допустимы конечные значения от 0 до 604800 секунд на событие. Неизвестные Track ID отклоняются внешним ключом. Все операции проверяют окно, главный кадр и URL отправителя, а изменяющие операции — также значения DTO.

Ошибка записи истории или лайка отображается в интерфейсе. Автоматического восстановления незаписанных событий после отказа диска или аварийного завершения нет. Незавершённая сессия остаётся с началом; будущий рекомендатель должен учитывать отсутствие терминального события. История пока возвращается целиком; пагинация и политика хранения нужны при росте объёма.

## Данные для Recommendation Engine

`ListeningDataReader.getListeningData()` — независимый от Electron и React контракт чтения, объявленный в `src/shared/contracts.ts`. Его реализует `LibraryStore`. Снимок содержит обычные DTO `TrackPreference[]` и `PlaybackEvent[]`, без путей и объектов SQLite. Renderer читает его через именованный `getListeningData()` в Preload; изменения — через `setTrackPreference(trackId, liked)` и `recordPlaybackEvent(event)`.

Предлагаемый будущий интерфейс чистого алгоритма:

```ts
interface RecommendationContext {
  candidates: readonly Track[] // Main заранее отбирает доступные источники
  preferences: readonly TrackPreference[]
  history: readonly PlaybackEvent[]
  now: string
  seed: number
}
type RecommendationEngine = (
  context: RecommendationContext,
  count: number,
) => string[] // упорядоченные Track ID
```

Алгоритм получает снимок от вызывающего слоя и не читает БД. Ошибки, `ended` без дослушивания и незавершённые сессии следует отличать от отрицательной реакции `skipped`. «Волна» в этом этапе не реализуется.
