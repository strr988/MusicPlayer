# Слепое сравнение рекомендаций

## Гипотеза

В условиях фиксированного локального каталога слушатели могут оценить рекомендации Personal Wave выше Random и Preference Baseline. Основные сравнения — парные разницы средних оценок одного участника C−A и C−B. Малый пилот предназначен для проверки процедуры и оценки разброса.

## Техническая методика

| Метод | Правило |
| --- | --- |
| A · Random | Перемешивание доступных уникальных треков с seed, выбор первых позиций. |
| B · Preference Baseline | Три слагаемых лайков, общих с C. Лайк трека даёт +6, совпадение исполнителя +2, совпадение жанра +1. Равные баллы разрешаются тем же перемешиванием. |
| C · Personal Wave | Те же слагаемые лайков плюс новизна, дослушивания и пропуски, фильтры недавних треков и соседних исполнителей, поиск новых треков в выбранном режиме. |

Для каждого запуска все методы получают один снимок каталога, доступности, реакций и истории, одно время `now`, одинаковые seed и длину. Снимок замораживается до первого предъявления. Состояние генератора создаётся заново при каждом запуске. Ответы пилота остаются в форме и не входят в снимок. Тестирование сравнивает статические очереди. В живой «Волне» плеер пересчитывает список по ходу прослушивания.

```powershell
node scripts/compare-recommendations.mjs --example 8 42,43,44,45,46,47
node scripts/compare-recommendations.mjs snapshot.json 8 42,43,44,45,46,47
```

`algorithm-benchmark` содержит метрики по каждому seed и средние по запускам. Доля разнообразия — число разных известных исполнителей среди треков с известным исполнителем. Доля соседних повторов исполнителя считается по парам, где известны оба. `repeatedTracks` — лишние вхождения ID внутри списка. `historyRepeats` — пересечения с окном недавних начал размером до пяти и не более числа доступных треков минус один. Доля новых — треки без `started` до момента снимка среди выданных. Если знаменатель пуст, возвращается `null`; среднее использует определённые значения. Время — медиана и p95 ста чистых генераций после двадцати прогревов. Агрегат времени усредняет эти показатели по запускам. Импорт, чтение базы, IPC и воспроизведение в замер не входят.

## Организатор

1. Зафиксируйте версию, разрешённый музыкальный каталог, настройки громкости и оборудования, число рекомендаций, длительность фрагмента, режим и список seed. Практический старт — 6–12 добровольцев, 8 позиций на метод, 30 секунд и «Баланс». Проверьте декодирование файлов и пригодность первых фрагментов. Синтетические демофайлы подходят для проверки программы.
2. Для каждого участника создайте локальный снимок. До предъявления дайте одинаковую возможность указать лайки на общем каталоге. Если собираете историю в ознакомительном прослушивании, используйте одинаковые правила записи и время на ознакомление. Если история отсутствует, используйте пустой массив. Фиксируйте только реальные предпочтения и события. Сохраняйте один снимок на все три метода и договоритесь об общем каталоге. Установите `now` после сбора стартовых сигналов и задайте seed из заранее составленного списка.
3. Последовательно выдавайте слоты 1–6. Генератор использует ABC, ACB, BAC, BCA, CAB и CBA по одному разу в каждом блоке из шести. Если кто-то откажется, оставьте пропуск в журнале слотов. Храните журнал без имён.
4. Сгенерируйте папку сессии. Например, для первого слота и двух позиций в короткой репетиции запустите команду ниже. На пилоте используйте заранее зафиксированные параметры.

```powershell
node scripts/prepare-pilot.mjs snapshot.json audio-map.json session-01 1 2 30
```

5. На том же компьютере откройте `session-01/participant/listen.html` в браузере. Форма офлайн, использует локальные аудиофайлы и один плеер с одинаковыми настройками. HTML содержит локальные адреса аудио для воспроизведения. Держите его рядом с машиной исследования. Снимок и `organizer-key.json` храните у организатора. Откройте участнику только форму с номерами подборок. Предварительно проверьте воспроизведение в том же браузере и возможность загрузить JSON.
6. По окончании доброволец сам скачивает и передаёт JSON. Записывайте число приглашённых, отказов и выходов без файла в отдельном обезличенном журнале. Включайте в анализ только переданные ответы. Храните ключи, ответы и журнал локально. Объясните, до какого момента можно отозвать файл с оценками по коду сессии.

## Доброволец

Участие добровольное. Последовательно прослушайте три подборки при той же громкости и оценивайте каждый трек по соответствию вкусу от 1 («совсем не подходит») до 5 («отлично подходит»). Форма останавливает звук у заданной границы фрагмента. Слушайте с начала, оставьте громкость постоянной и не перематывайте. Можно отметить, слышали ли вы трек до эксперимента. Если запись не воспроизводится, отметьте ошибку. Любую позицию можно оставить без оценки.

В любой момент можно завершить участие без сохранения. На последнем треке выберите **Скачать оценки** и подтвердите загрузку, если хотите передать ответы. В файле есть случайный код сессии, ручные оценки и отметки. Передача файла организатору выполняется вами.

## Форматы данных и проверка

Снимок — UTF-8 JSON. Пример структуры с двумя записями и одним стартовым лайком. Значения в собственном снимке берутся из реального каталога и ответов участника.

```json
{
  "now": 1794355200000,
  "seed": 42,
  "mode": "balance",
  "candidates": [
    { "id": "t01", "artist": "Исполнитель", "genres": ["рок"], "available": true },
    { "id": "t02", "artist": null, "genres": [], "available": true }
  ],
  "listening": {
    "preferences": [{ "trackId": "t01", "liked": true, "updatedAt": "2026-11-10T20:00:00Z" }],
    "events": []
  }
}
```

Для существующей истории в `events` укажите `trackId`, `sessionId`, `type` (`started`, `completed`, `skipped`, `ended`, `error`), `listenedSeconds` и `timestamp` в ISO 8601. Даты реакций должны быть не позднее `now`. Каталог использует уникальные непрозрачные ID. В `audio-map.json` укажите ровно доступные ID и пути относительно карты. Пример — `{"t01":"audio/song1.mp3","t02":"audio/song2.flac"}`.

Форма выгружает `pilot-ratings` версии 2, случайный `sessionId` и три массива `blocks` в предъявленном порядке. Длина каждого массива равна запланированной длине. Позиция содержит `{"status":"rated","rating":4,"familiarity":null}`, `{"status":"missing"}` или `{"status":"audio-error"}`. Допустимые значения знакомства — `yes`, `no`, `null`. Схема 2 связывает ответ с ключом, подготовленным заранее. Ввод в старом формате 0.4.1 не принимается.

```powershell
node scripts/export-pilot-results.mjs --check session-01/organizer-key.json ratings-01.json
node scripts/export-pilot-results.mjs pilot-report.json session-01/organizer-key.json ratings-01.json session-02/organizer-key.json ratings-02.json
node scripts/plot-pilot-results.mjs pilot-report.json pilot-chart.svg
```

Передайте по паре файлов на каждый отправленный ответ. Проверка отклоняет лишние поля, неверные значения, несовпадающие коды, дубли сессий или слотов, смешанные форматы и разные длины, режимы либо длительности фрагмента. Экспорт создаёт новый файл, сохраняет фактические оценки и статусы позиций без кодов сессий, ID треков, имён, тегов или путей. Раздел `technical` содержит объём каталога, параметры по сессиям и метрики, пересчитанные из сохранённых снимков. Раздел `userExperiment` содержит ответы, пропуски, ошибки, число участников с ответами и число оценок. При отсутствии оценок создаётся только технический отчёт со счётчиками неполных данных. Сессии без переданного файла учитываются вручную по журналу.

## Анализ и ограничения

Каждый слушатель имеет одинаковый вес при усреднении. Для каждого парного сравнения используются слушатели с хотя бы одной оценкой в обоих условиях. График показывает индивидуальные средние, среднее группы, парные разницы и размеры выборок. Сессии с неполными данными учитываются в отчёте с указанием пропусков и ошибок. Отдельно проверьте, меняются ли выводы, если оставить только полностью оценённые сессии.

Порядок предъявления, узнаваемые записи, повторы между подборками, короткие фрагменты и малый каталог могут влиять на ответы. Частоты «раньше не слышал» по журналу и по самоотчёту имеют разный смысл. По окончании пилота опишите наблюдаемые оценки, пропуски и разброс. Фактический статус и технические измерения находятся в [отчёте о результатах](EXPERIMENT_RESULTS.md).
