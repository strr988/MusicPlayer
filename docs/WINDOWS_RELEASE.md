# mustplay 0.8.0 для Windows x64

Инструкция предназначена для локально собранного Windows ZIP.

## Запуск и демонстрация

1. В Проводнике выберите **Извлечь всё** для `mustplay-0.8.0-win-x64.zip`. Сохраните все файлы распакованной папки рядом друг с другом.
2. Откройте **mustplay.exe** в папке **mustplay 0.8.0**. В архиве уже есть Electron и все runtime-зависимости. Для запуска достаточно Windows x64.
3. Нажмите **Добавить папку** и укажите папку с разрешёнными MP3 и FLAC. После добавления файлов в эту папку нажмите **Обновить**.
4. Найдите треки по названию или альбому и отсортируйте по длительности. Запустите оба формата из таблицы. Покажите паузу, перемотку, следующий трек и кнопку **Без звука**. Отметьте трек сердцем, откройте раздел **Моя волна** и нажмите **Запустить волну**. Раскройте **Почему этот трек?** и **Технические подробности**. Выберите строку в таблице, чтобы вернуться к последовательной очереди.
5. Создайте плейлист с обоими треками, переставьте их и запустите плейлист. В разделе **Моя волна** выберите режим **Открытия**.
6. Воспользуйтесь действиями **Воспроизвести следующим** и **Добавить в очередь**. Откройте очередь кнопкой в плеере, измените порядок и закройте панель клавишей **Escape**. Включите Shuffle или повтор и поставьте плеер на паузу. После перезапуска проверьте очередь и позицию. Нажмите **Воспроизвести**, чтобы продолжить.
7. Переключите тему кнопкой в боковой панели. Проверьте, что она применяется в мини-плеере и сохраняется после перезапуска.
8. Откройте **Текстомузыку** кнопкой в плеере на треке с LRC. Нажмите строку для перемотки и переключитесь на **Читать текст**. В **Настройках** измените силу пульсации «Моей волны». Откройте мини-плеер кнопкой в нижнем плеере. [Руководство по функциям плеера](PLAYER_EXPERIENCE.md).

## Ручная проверка на машине показа

- [ ] Сравнить SHA-256 ZIP с записанной рядом суммой через `Get-FileHash .\mustplay-0.8.0-win-x64.zip`. При первом запуске записать версию Windows и реакцию SmartScreen или политики организации.
- [ ] Распаковать в каталог с пробелами, запустить в новом профиле Windows и проверить пустую библиотеку. Отключить сеть до запуска и оставить её отключённой на время сценария.
- [ ] Выбрать папку через системный диалог, проверить MP3, FLAC, теги и слышимый звук. Повторить импорт и проверить отсутствие дублей. Сравнить контрольные суммы аудио до и после.
- [ ] На разрешённых файлах со встроенными JPEG или PNG проверить обложки в таблице и в плеере. У демотреков без обложек отображается значок ноты. Проверить поиск, сортировку и регулятор громкости в окне минимальной ширины.
- [ ] Поставить лайк, запустить «Волну», перейти к следующему треку и дождаться автоматического перехода. С одним доступным треком очередь должна остановиться. При недоступных источниках должно появиться сообщение.
- [ ] Создать и переименовать плейлист, добавить композиции, изменить их порядок и проверить очередь. Убрать одну композицию и проверить её в библиотеке. Закрыть приложение, переместить один тестовый файл и проверить пометку о недоступности и воспроизведение остальных треков.
- [ ] Во время воспроизведения проверить назначенное глобальное сочетание при фокусе в другом приложении. Проверить Play/Pause, Next и Previous с физической клавиатуры или гарнитуры в активной медиасессии Windows.
- [ ] Включить таймер «После текущего трека» в режиме Repeat One. Проверить затухание, остановку в конце трека и исходный уровень громкости после остановки.
- [ ] Закрыть окно, перенести распакованное приложение в другой каталог, сохранив папку музыки на прежнем месте, и запустить снова. Проверить библиотеку, лайк и воспроизведение. Проверить, что `library.sqlite3` находится в `%APPDATA%\mustplay`.
- [ ] Повторно закрыть окно и проверить отсутствие зависших процессов приложения и системных сообщений о сбое.

## Сборка из исходников

Сборка рассчитана на Windows x64 с Node.js 24.22.x и pnpm 11.25.0. Используется Electron 45.3.0 из зафиксированных зависимостей.

```powershell
pnpm install --frozen-lockfile --store-dir .pnpm-store
pnpm exec install-electron
pnpm package:windows
pnpm test:release
```

Первые две команды подготавливают локальный store и Windows-бинарники Electron. Упаковка использует этот store офлайн с `--frozen-lockfile`, production-зависимости раскладываются без install-скриптов. Штатный Windows `tar.exe` создаёт ZIP в `release`. Рядом сохраняется SHA-256. Это переносимый каталог приложения с `resources/app`. Лицензии Electron и Chromium находятся в корне распакованной папки, лицензии runtime-пакетов входят в их каталоги.

GitHub Actions проверяет установку по lockfile, TypeScript, сборку и модульные тесты на Windows. Десктопные сценарии и проверки ZIP выполняются отдельно в интерактивном сеансе Windows x64. Сценарии миграции используют локальные архивы предыдущих выпусков, указанные ниже.

## Сторонние компоненты ZIP

Сборка использует DLL из официального Windows x64-дистрибутива Electron 45.3.0. В их числе `ffmpeg.dll`, DirectX Shader Compiler и SwiftShader. Уведомления Electron и Chromium находятся в `LICENSE` и `LICENSES.chromium.html` в корне распакованной папки. Уведомления npm-пакетов находятся внутри `resources/app/node_modules`. [Дистрибутив Electron 45.3.0](https://github.com/electron/electron/releases/tag/v45.3.0).

### FFmpeg в проверенном архиве

Electron 45.3.0 использует Chromium 156.0.8078.96 с ревизией FFmpeg `9db86ce5b5b454dfc96c435f9f0723012980c37f`. Хеш `ffmpeg.dll` в тестовом ZIP совпадает с файлом из официального дистрибутива Electron. Его конфигурация использует `ffmpeg_branding = "Chrome"` и `proprietary_codecs = true`. На Windows x64 отключены `CONFIG_GPL`, `CONFIG_GPLV3`, `CONFIG_VERSION3` и `CONFIG_NONFREE`. Для сборки применяется LGPL-2.1-or-later, отдельные файлы имеют собственные уведомления. [Конфигурация Electron](https://github.com/electron/electron/blob/v45.3.0/build/args/all.gn) · [Конфигурация FFmpeg](https://chromium.googlesource.com/chromium/third_party/ffmpeg/+/9db86ce5b5b454dfc96c435f9f0723012980c37f/chromium/config/Chrome/win/x64/config.h).

В списке FFmpeg для этой конфигурации есть декодеры MP3, FLAC, AAC, H.264, Vorbis, Opus и PCM. Возможности FFmpeg шире форматов импорта mustplay. Патентные условия AAC и H.264 оцениваются отдельно от LGPL с учётом территории, использования и применимых прав распространителя. [Список декодеров](https://chromium.googlesource.com/chromium/third_party/ffmpeg/+/9db86ce5b5b454dfc96c435f9f0723012980c37f/chromium/config/Chrome/win/x64/libavcodec/codec_list.c) · [AAC](https://www.via-la.com/licensing-programs/aac/) · [AVC/H.264](https://www.via-la.com/licensing-programs/avc-h-264/).

### Подготовка Windows ZIP к распространению

1. Использовать официальный альтернативный `ffmpeg-v45.3.0-win32-x64.zip` для той же версии Electron и архитектуры. В нём `ffmpeg_branding = "Chromium"` и `proprietary_codecs = false`. Эта конфигурация сохраняет декодеры MP3 и FLAC. Оба формата воспроизвелись в сценарии «Моей волны» с альтернативной DLL во временной копии Electron. [Официальный дистрибутив](https://github.com/electron/electron/releases/tag/v45.3.0) · [Конфигурация альтернативной сборки](https://github.com/electron/electron/blob/v45.3.0/build/args/ffmpeg.gn).
2. Сохранить уведомления и полный текст LGPL. В дистрибутиве и рядом со скачиванием явно указать использование FFmpeg и расположение лицензии и соответствующих исходников. Для опубликованной DLL предоставить доступ к точным исходникам FFmpeg с патчами Electron и файлами конфигурации, а также инструкциям и параметрам сборки Windows x64. В инструкции зафиксировать ревизии Chromium и Electron, команду сборки и способ проверки хеша DLL. [LGPL 2.1, §§ 4 и 6](https://www.gnu.org/licenses/old-licenses/lgpl-2.1.html) · [Исходники FFmpeg](https://chromium.googlesource.com/chromium/third_party/ffmpeg/+/9db86ce5b5b454dfc96c435f9f0723012980c37f) · [Патчи Electron](https://github.com/electron/electron/tree/v45.3.0/patches/ffmpeg) · [Сборка Electron](https://www.electronjs.org/docs/latest/development/build-instructions-windows/).
3. Оставить `ffmpeg.dll` отдельным файлом рядом с EXE. Условия распространения должны позволять пользователю менять библиотеку и выполнять обратную разработку для отладки этих изменений. Проверить загрузку совместимой заменённой DLL после распаковки будущего ZIP. [LGPL 2.1, § 6](https://www.gnu.org/licenses/old-licenses/lgpl-2.1.html).
4. До публикации проверить соответствующие исходники и уведомления, применимые права распространения выбранного комплекта и весь распакованный ZIP. Выполнить сценарии MP3/FLAC и миграции, опубликовать SHA-256 нового архива. Исходный тестовый ZIP 0.5.0 хранится локально.

## Проверка обновления

```powershell
$env:MUSTPLAY_011_ZIP = (Resolve-Path .\release\MusicPlayer-0.1.1-win-x64.zip).Path
$env:MUSTPLAY_020_ZIP = (Resolve-Path .\release\MusicPlayer-0.2.0-win-x64.zip).Path
$env:MUSTPLAY_030_ZIP = (Resolve-Path .\release\MusicPlayer-0.3.0-win-x64.zip).Path
$env:MUSTPLAY_040_ZIP = (Resolve-Path .\release\MusicPlayer-0.4.0-win-x64.zip).Path
$env:MUSTPLAY_041_ZIP = (Resolve-Path .\release\MusicPlayer-0.4.1-win-x64.zip).Path
$env:MUSTPLAY_050_ZIP = (Resolve-Path .\release\MusicPlayer-0.5.0-win-x64.zip).Path
$env:MUSTPLAY_060_ZIP = (Resolve-Path .\release\MusicPlayer-0.6.0-win-x64.zip).Path
pnpm test:release
Remove-Item Env:MUSTPLAY_011_ZIP, Env:MUSTPLAY_020_ZIP, Env:MUSTPLAY_030_ZIP, Env:MUSTPLAY_040_ZIP, Env:MUSTPLAY_041_ZIP, Env:MUSTPLAY_050_ZIP, Env:MUSTPLAY_060_ZIP
```

Тесты создают профили исходными EXE 0.1.1 и 0.2.0. После запуска 0.8.0 они сверяют схему и данные существующих таблиц. Для профилей 0.3.0 и 0.4.0 тесты проверяют восстановление очереди и позиции, а для 0.4.1 — историю, реакции и продолжение «Волны». Резервная копия схемы 4 проверяется открытием в исходном EXE 0.2.0 с отдельным временным профилем. Проверка профиля 0.5.0 сверяет очередь в резервной копии схемы 5 и её восстановление в 0.8.0.

## Известные ограничения

- Сборка ориентирована на Windows x64 и демонстрационный каталог. У пакета нет подписи издателя mustplay. SmartScreen и политики организации могут повлиять на запуск.
- Новые профили создаются в `%APPDATA%\mustplay`, отдельно от распакованного приложения. При обновлении используется существующий профиль `%APPDATA%\Music Player`, если в новом каталоге ещё нет базы. Библиотека ссылается на исходные файлы по локальным путям. Для переноса музыки на другой компьютер потребуется импорт на нём.
- Текущая сборка 0.8.0 использует схему 12. Для возврата к 0.7.0 используйте копию схемы 11 в отдельном профиле. [Миграции и резервное копирование](PERSISTENT_LIBRARY.md#миграции-и-запись-данных).
- Обложки читаются из встроенных JPEG и PNG с ограничениями по размеру. Интерфейс проверен на синтетических каталогах до 10 000 композиций. [Методика и ограничения](PERFORMANCE_REPORT.md).
- Алгоритм использует эвристические веса. Короткий каталог ограничивает выбор. Для оценки попадания во вкус нужен пилот с участниками.
