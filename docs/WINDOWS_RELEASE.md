# Music Player 0.5.0 для Windows x64

## Запуск и демонстрация

1. В Проводнике выберите **Извлечь всё** для `MusicPlayer-0.5.0-win-x64.zip`. Сохраните все файлы распакованной папки рядом друг с другом.
2. Откройте **Music Player.exe** в папке **Music Player 0.5.0**. В архиве уже есть Electron и все runtime-зависимости. Для запуска достаточно Windows x64.
3. Нажмите **Выбрать папку**, укажите **Demo audio** или папку с разрешёнными MP3 и FLAC. В демонстрационной папке два коротких синтетических тона с тестовыми тегами.
4. Найдите треки по запросу `fixture album` и отсортируйте по длительности. Запустите оба формата из таблицы. Покажите паузу, перемотку, следующий трек и кнопку **Без звука**. Отметьте трек сердцем, откройте раздел **Моя волна** и нажмите **Запустить волну**. Раскройте **Почему этот трек?** и **Технические подробности**. Выберите строку в таблице, чтобы вернуться к последовательной очереди.
5. Создайте плейлист с обоими треками, переставьте их и запустите плейлист. В разделе **Моя волна** выберите режим **Открытия**.
6. Воспользуйтесь действиями **Воспроизвести следующим** и **Добавить в очередь**. Откройте очередь кнопкой в плеере, измените порядок и закройте панель клавишей **Escape**. Включите Shuffle или повтор и поставьте плеер на паузу. После перезапуска проверьте очередь и позицию. Нажмите **Воспроизвести**, чтобы продолжить.

## Ручная проверка на машине показа

- [ ] Сравнить SHA-256 ZIP с опубликованной рядом суммой через `Get-FileHash .\MusicPlayer-0.5.0-win-x64.zip`. При первом запуске записать версию Windows и реакцию SmartScreen или политики организации.
- [ ] Распаковать в каталог с пробелами, запустить в новом профиле Windows и проверить пустую библиотеку. Отключить сеть до запуска и оставить её отключённой на время сценария.
- [ ] Выбрать папку через системный диалог, проверить MP3, FLAC, теги и слышимый звук. Повторить импорт и проверить отсутствие дублей. Сравнить контрольные суммы аудио до и после.
- [ ] На разрешённых файлах со встроенными JPEG или PNG проверить обложки в таблице и в плеере. У демотреков без обложек отображается значок ноты. Проверить поиск, сортировку и регулятор громкости в окне минимальной ширины.
- [ ] Поставить лайк, запустить «Волну», перейти к следующему треку и дождаться автоматического перехода. С одним доступным треком очередь должна остановиться. При недоступных источниках должно появиться сообщение.
- [ ] Создать и переименовать плейлист, добавить композиции, изменить их порядок и проверить очередь. Убрать одну композицию и проверить её в библиотеке. Закрыть приложение, переместить один тестовый файл и проверить пометку о недоступности и воспроизведение остальных треков.
- [ ] Во время воспроизведения проверить Play/Pause, Next и Previous с физической клавиатуры или гарнитуры в активной медиасессии Windows.
- [ ] Закрыть окно, перенести распакованное приложение в другой каталог, сохранив папку музыки на прежнем месте, и запустить снова. Проверить библиотеку, лайк и воспроизведение. Проверить, что `library.sqlite3` находится в `%APPDATA%\Music Player`.
- [ ] Повторно закрыть окно и проверить отсутствие зависших процессов приложения и системных сообщений о сбое.

## Сборка из исходников

Сборка рассчитана на Windows x64 с Node.js 24.22.x и pnpm 11.25.0. Используется Electron 45.3.0 из зафиксированных зависимостей.

```powershell
pnpm install --frozen-lockfile --store-dir .pnpm-store
pnpm exec install-electron
pnpm package:windows
pnpm test:release
```

Первые две команды подготавливают локальный store и Windows-бинарники Electron. Упаковка использует этот store офлайн с `--frozen-lockfile`, production-зависимости раскладываются без install-скриптов. Штатный Windows `tar.exe` создаёт ZIP в `release`. Рядом сохраняется SHA-256. Это переносимый каталог приложения с `resources/app`. Лицензии Electron и Chromium находятся в корне распакованной папки, лицензии runtime-пакетов входят в их каталоги.

GitHub Actions проверяет установку по lockfile, TypeScript, сборку и модульные тесты на Windows. Десктопные сценарии и проверки ZIP выполняются отдельно в интерактивном сеансе Windows x64. Сценарии миграции используют локальные архивы предыдущих выпусков, указанные ниже.

## Сторонние компоненты ZIP

Сборка использует DLL из официального Windows x64-дистрибутива Electron 45.3.0. В их числе `ffmpeg.dll`, DirectX Shader Compiler и SwiftShader. Уведомления Electron и Chromium находятся в `LICENSE` и `LICENSES.chromium.html` в корне распакованной папки. Уведомления npm-пакетов находятся внутри `resources/app/node_modules`. [Дистрибутив Electron 45.3.0](https://github.com/electron/electron/releases/tag/v45.3.0).

Для распространения `ffmpeg.dll` необходимо выполнить условия LGPL для соответствующих исходников, включая патчи и настройки сборки. Electron 45.3.0 использует Chromium 156.0.8078.96 с ревизией FFmpeg `9db86ce5b5b454dfc96c435f9f0723012980c37f`. В конфигурации Electron включены дополнительные кодеки (`proprietary_codecs = true`, `ffmpeg_branding = "Chrome"`). Условия распространения этой конфигурации зависят от конкретных кодеков и территории. [Исходники FFmpeg](https://chromium.googlesource.com/chromium/third_party/ffmpeg/+/9db86ce5b5b454dfc96c435f9f0723012980c37f) · [Патчи Electron](https://github.com/electron/electron/tree/v45.3.0/patches/ffmpeg) · [Конфигурация Electron](https://github.com/electron/electron/blob/v45.3.0/build/args/all.gn) · [Условия распространения FFmpeg](https://ffmpeg.org/legal.html).

## Проверка обновления

```powershell
$env:MUSIC_PLAYER_011_ZIP = (Resolve-Path .\release\MusicPlayer-0.1.1-win-x64.zip).Path
$env:MUSIC_PLAYER_020_ZIP = (Resolve-Path .\release\MusicPlayer-0.2.0-win-x64.zip).Path
$env:MUSIC_PLAYER_030_ZIP = (Resolve-Path .\release\MusicPlayer-0.3.0-win-x64.zip).Path
$env:MUSIC_PLAYER_040_ZIP = (Resolve-Path .\release\MusicPlayer-0.4.0-win-x64.zip).Path
$env:MUSIC_PLAYER_041_ZIP = (Resolve-Path .\release\MusicPlayer-0.4.1-win-x64.zip).Path
pnpm test:release
Remove-Item Env:MUSIC_PLAYER_011_ZIP, Env:MUSIC_PLAYER_020_ZIP, Env:MUSIC_PLAYER_030_ZIP, Env:MUSIC_PLAYER_040_ZIP, Env:MUSIC_PLAYER_041_ZIP
```

Тесты создают профили исходными EXE 0.1.1 и 0.2.0. После запуска 0.5.0 они сверяют схему и данные существующих таблиц. Для профилей 0.3.0 и 0.4.0 тесты проверяют восстановление очереди и позиции, а для 0.4.1 — историю, реакции и продолжение «Волны». Резервная копия схемы 4 проверяется открытием в исходном EXE 0.2.0 с отдельным временным профилем.

## Известные ограничения

- Сборка ориентирована на Windows x64 и демонстрационный каталог. У пакета нет подписи издателя Music Player. SmartScreen и политики организации могут повлиять на запуск.
- SQLite и профиль хранятся в `%APPDATA%\Music Player`, отдельно от распакованного приложения. Библиотека ссылается на исходные файлы по локальным путям. Для переноса музыки на другой компьютер потребуется импорт на нём.
- Версия 0.5.0 использует схему 5, введённую в 0.3.0. Для возврата к 0.2.0 или более раннему выпуску используйте резервную копию подходящей схемы в отдельном профиле. [Миграции и резервное копирование](PERSISTENT_LIBRARY.md#миграции-и-запись-данных).
- Обложки читаются из встроенных JPEG и PNG с ограничениями по размеру. Интерфейс проверен на синтетических каталогах до 10 000 композиций. [Методика и ограничения](PERFORMANCE_REPORT.md).
- Алгоритм использует эвристические веса. Короткий каталог ограничивает выбор. Для оценки попадания во вкус нужен пилот с участниками.
