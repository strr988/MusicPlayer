# Интеграция yt-dlp

## Локальная установка

На Windows x64 откройте **Настройки → Модули** или нажмите **Установить модуль** в разделе **Загрузки**. Подтвердите предложенный выпуск Stable. Карточка показывает скачивание, проверку целостности и проверку провайдеров. Уже введённая ссылка остаётся в поле, после установки можно сразу нажать **Анализировать ссылку**.

В настройках видны состояние, установленная версия, последний найденный Stable Release, дата и результат проверки. **Проверить обновления** получает метаданные GitHub. Для установки найденной версии используйте **Обновить** и подтвердите выпуск. При повреждении доступна переустановка. После успешного обновления можно восстановить предыдущую версию. Удаление управляемого модуля сохраняет библиотеку, файлы и журнал загрузок.

## Проверка выпуска и хранение

Main запрашивает `yt-dlp/yt-dlp/releases/latest` через GitHub API и принимает артефакты `yt-dlp.exe`, `SHA2-256SUMS` и `SHA2-256SUMS.sig` из конкретного выпуска. HTTPS, адреса файлов и перенаправления проверяются. Скачивание ограничено размером артефакта и таймаутом. SHA-256 из GitHub должен совпасть с подписанной суммой. Подпись проверяется OpenPGP.js по ключу издателя с отпечатком `AC0C BBE6 848D 6A87 3464 AF4E 57CF 6593 3B5A 7581`. Windows x64 проверяется по PE-заголовку. Смена ключа или формата подписи требует обновления политики доверия Music Player. [Ключ издателя](https://github.com/yt-dlp/yt-dlp/blob/2026.10.26/public.key) · [Файлы выпуска](https://github.com/yt-dlp/yt-dlp/releases/expanded_assets/2026.10.26).

Версия и подписанные данные сохраняются в реестре модуля в профиле. Перед каждым запуском Main заново сверяет бинарник с подписанными данными, создаёт временную копию из проверенных байтов и сравнивает `--version` с выбранным тегом. Старый файл из `tools` пользовательского профиля не используется. Для новой версии выполняется пробный анализ контрольных записей Archive.org и SoundCloud теми же провайдерами, что обслуживают «Загрузки». Если сеть или контрольная запись недоступны, установка приостанавливается с сообщением об ошибке. Можно повторить операцию позже. [Проверочный материал](MUSIC_SOURCES.md#проверенный-материал).

Операции замены и удаления выполняются последовательно, когда нет активных анализов, загрузок или импортов. Приложение готовит кандидата в отдельном каталоге профиля и атомарно переключает реестр после успешной проверки. При ошибке и отмене активная версия сохраняется. Незавершённые установки очищаются, включая восстановление после перезапуска. После успешного обновления хранится одна предыдущая проверенная версия для отката, доступного офлайн при целых файлах. Обновление модуля действует отдельно от версий и обновления самого Music Player.

Main хеширует байты перед созданием рабочей копии, проверяет `--version`, запускает её без оболочки, ограничивает вывод и время работы. Системный PATH для поиска yt-dlp, пользовательская конфигурация, кеш, cookies, внешний JS runtime, удалённые компоненты и плагины отключены. FFmpeg не нужен для включённого сценария. Автообновление утилиты отсутствует.

Для анализа yt-dlp получает одноразовый loopback HTTPS CONNECT-прокси с отдельным списком точных хостов для каждого провайдера. Archive.org использует `archive.org:443`. SoundCloud использует `soundcloud.com`, `api-v2.soundcloud.com`, `a-v2.sndcdn.com`, `a1.sndcdn.com` и `i1.sndcdn.com` на порту 443. Main повторно проверяет HTTPS, хост и путь при прямом получении метаданных, обложки или оригинала и на каждом перенаправлении. Перед соединением DNS-ответ проверяется на непубличные адреса. Соединение использует проверенный IPv4 и исходное TLS-имя. Фильтр ограничивает штатный сетевой трафик проверенного бинарника. Права процесса определяет ОС.

SoundCloud запускается в режиме анализа с одним встроенным extractor и отключённым скачиванием. Из stdout сохраняются только нормализованные поля. Из stderr распознаётся сообщение о входе для оригинала. Адреса потоков, временные подписи и сырая диагностика остаются внутри Main. PNG и JPEG выдаются по внутреннему ID после проверки размера и содержимого. [Сценарий SoundCloud](MUSIC_SOURCES.md#soundcloud), [закреплённый extractor](https://github.com/yt-dlp/yt-dlp/blob/2026.10.26/yt_dlp/extractor/soundcloud.py).

## Прямая загрузка SoundCloud

- **Оригинал.** В yt-dlp `2026.10.26` extractor обращается к веб-эндпоинту `/tracks/{id}/download`, когда запись допускает скачивание и лимит загрузок ещё доступен. Успешный ответ содержит адрес для получения исходного файла. Формат помечается `download` и `Original`. Ответ 401 означает, что нужен вход. Extractor использует OAuth-токен или cookie с таким токеном. Music Player запускает yt-dlp без учётных данных. [Код extractor](https://github.com/yt-dlp/yt-dlp/blob/2026.10.26/yt_dlp/extractor/soundcloud.py), [официальный веб-сценарий](https://help.soundcloud.com/hc/en-us/articles/115003448787-Downloading-tracks).
- **Проверка без скачивания.** Выбор формата `download` в режиме симуляции вернул «формат недоступен» на «Convergence» (Scott Buckley, CC BY 4.0). На публичном «The Following» (80M) та же проверка дополнительно вернула предупреждение о входе. Скачивание исходного файла после авторизации не проверялось. Для теста импорта «Convergence» использован MP3, опубликованный автором на своём сайте. [Релиз и разрешение автора](https://www.scottbuckley.com.au/library/convergence/).
- **Потоки.** AAC/HLS выдаётся отдельной веткой transcodings. Сегменты содержат версию, подготовленную для воспроизведения SoundCloud. На «Convergence» обнаружены варианты 96 и 160 кбит/с. Декодирование синтетического AAC/HLS проверено отдельно в Electron. Потоки с SoundCloud во время проверки не сохранялись. [Руководство по потокам](https://developers.soundcloud.com/docs/api/guide#playing-tracks).
- **Граница реализации.** Документация SoundCloud описывает OAuth для зарегистрированных приложений. Раздел *Caching and Downloading* условий API ограничивает постоянное сохранение аудио даже при включённой автором веб-загрузке. Для прямой интеграции понадобятся разрешённый SoundCloud способ получения оригинала и сквозная проверка на собственной записи с включённой загрузкой. В 0.6.0 доступны официальный браузерный сценарий и импорт локального MP3/FLAC. [Документация OAuth](https://developers.soundcloud.com/docs/api/guide#authentication), [условия API](https://developers.soundcloud.com/docs/api/terms-of-use#caching-and-downloading).

Список разрешённых лицензий опирается на декларацию источника и публичную доступность файла. Приложение не устанавливает юридическую принадлежность прав загрузившего запись. Для проверочного материала дополнительно сверены указанный автор, метаданные зеркала Jamendo и файл License.txt. [Правила Archive.org](https://archive.org/about/terms), [описание проверочного материала](MUSIC_SOURCES.md#проверенный-материал).

## Плагины

В 0.6.0 диагностика фиксирует эффективный режим запуска `--no-plugin-dirs`. Ручная загрузка и перечисление глобально установленных плагинов отключены. Интерфейс MusicSourceProvider допускает отдельный адаптер после аудита. Для доверенного расширения потребуется отдельный каталог, закреплённый релиз и SHA-256, просмотр кода и лицензии, явное включение, диагностика активных extractor и postprocessor и изоляция от пользовательского профиля средствами ОС. Плагин Яндекс Музыки исследован по документации автора.

## Техническое исследование

На 12 ноября 2026 года GitHub API указывает Stable `2026.10.26`. Этот выпуск используется в тестовой копии подписанных метаданных. При установке и обновлении Music Player проверяет подпись и сумму конкретного выпуска. [Стабильный релиз](https://github.com/yt-dlp/yt-dlp/releases/latest).

### Границы лицензирования

- Исходники Music Player сохраняют MIT. Исходники yt-dlp распространяются под Unlicense. Официальная сборка PyInstaller, которую скачивает приложение, распространяется под GPLv3+ согласно upstream. Пользователь получает её напрямую от издателя после подтверждения. ZIP Music Player содержит приложение, а установленный модуль хранится в пользовательском профиле и вызывается как отдельный CLI-процесс. При будущем включении бинарника в распространяемый комплект нужно отдельно выполнить условия GPLv3+, включая уведомления и доступ к соответствующим исходникам. [Лицензии yt-dlp](https://github.com/yt-dlp/yt-dlp#license) · [Уведомления upstream](https://github.com/yt-dlp/yt-dlp/blob/2026.10.26/THIRD_PARTY_LICENSES.txt).
- OpenPGP.js 6.3.2 используется для проверки подписи в Main. Библиотека под LGPL-3.0-or-later остаётся отдельным заменяемым npm-пакетом. [Исходники OpenPGP.js](https://github.com/openpgpjs/openpgpjs/archive/refs/tags/v6.3.2.tar.gz) · [Сведения о Windows ZIP](WINDOWS_RELEASE.md#сторонние-компоненты-zip).
- Для будущего модуля FFmpeg необходимо оценить конкретную сборку, её конфигурацию и лицензии LGPL или GPL. Анализ и сохранение разрешённых оригиналов работают без CLI FFmpeg. Electron `ffmpeg.dll` предоставляет декодеры Chromium. [Лицензирование FFmpeg](https://ffmpeg.org/legal.html).

Для полноценной работы YouTube актуальный yt-dlp использует внешний JS runtime и совместимый yt-dlp-ejs. Официальный exe включает EJS, но runtime устанавливается отдельно. Доступность роликов также зависит от требований YouTube к клиентам и токенам. [EJS](https://github.com/yt-dlp/yt-dlp/wiki/EJS), [PO Token Guide](https://github.com/yt-dlp/yt-dlp/wiki/PO-Token-Guide).

CLI предоставляет `--skip-download --dump-single-json`, машиночитаемый `--progress-template` и код выхода с диагностикой в stderr. Обычный человекочитаемый вывод не является стабильным протоколом. При отмене хост должен завершить процесс и дождаться закрытия потоков и файлов. Отдельный процесс работает с правами пользователя. Плагины extractor и postprocessor загружают Python-код из namespace `yt_dlp_plugins`. Обнаружение охватывает системные и пользовательские конфигурации, каталог программы и Python paths. Плагины могут перекрывать встроенные обработчики. [Документация CLI и плагинов](https://github.com/yt-dlp/yt-dlp/tree/2026.10.26#usage-and-options).
