# Моя волна

Откройте **Моя волна** в левой панели и нажмите **Запустить волну**, чтобы начать радио из локальной библиотеки. В разделе отображаются текущий трек и состояние воспроизведения. Плеер сначала воспроизводит ожидающие ручные элементы. Когда они заканчиваются, следующий переход использует первый подходящий Track ID из свежего расчёта. **Предыдущий трек** использует историю текущей очереди. Ручной запуск композиции из таблицы переключает источник на библиотеку. [Порядок переходов, Shuffle и Repeat](PLAYBACK_QUEUE.md).

При пустой библиотеке запуск доступен после импорта. Если в библиотеке остались только недоступные файлы, плеер сообщает об этом. При единственном доступном треке «Волна» останавливается после окончания или команды перехода. Кнопка запуска позволяет прослушать его снова. При двух треках автоматический переход чередует их. Утрата доступа между расчётом и открытием файла отображается как ошибка воспроизведения. Следующая команда перехода пересчитает доступность.

## Данные и воспроизводимость

`src/recommendations/engine.ts` принимает `RecommendationContext` и максимальный размер очереди. Контекст включает каталог с `id`, `artist`, `genres`, `available`, снимок `ListeningDataReader.getListeningData()`, `now` в миллисекундах Unix, целочисленный 32-битный `seed` и необязательный `mode`. Результат содержит упорядоченные уникальные Track ID. Длина ограничена числом доступных треков. Сортировка ID перед перемешиванием и генератор Mulberry32 дают воспроизводимый результат при фиксированном снимке, времени, seed и режиме.

Main проверяет источники штатным механизмом библиотеки и передаёт снимок алгоритму. Preload предоставляет `getWaveQueue()` для получения до десяти ID и `getWaveRecommendations()` для получения тех же решений с диагностикой. Main проверяет окно, главный кадр, URL и отсутствие аргументов. Плеер ждёт завершения записи предыдущей сессии перед запросом, поэтому лайки и новые события влияют на ближайший пересчёт. Main выдаёт новый seed при каждом запросе. При перезапуске восстанавливаются текущий трек и ручная очередь. Свежие рекомендации рассчитываются по мере продолжения радио. [Правила записи событий](LISTENING_FEEDBACK.md).

## Формула ранжирования

Для каждого доступного трека вычисляется сумма.

| Признак | Баллы |
| --- | ---: |
| Трек отмечен лайком | +6 |
| Исполнитель совпадает с исполнителем хотя бы одного лайкнутого трека | +2 |
| Хотя бы один жанр совпадает с жанром лайкнутого трека | +1 |
| В истории отсутствует `started` для трека | +1 |
| Каждое `completed` за последние 30 суток, максимум два | +1 |
| Каждый `skipped` за последние 30 суток, максимум два | −4 |

Лайк на треке создаёт сигналы об исполнителе и жанрах. Учитываются и лайки недоступных треков, чьи теги сохранились в каталоге. Отменённый лайк снимает вклад соответствующего трека. Пробелы по краям и регистр тегов игнорируются. Пустые значения пропускаются. При паузе запись пропуска отсутствует. `started` влияет на новизну и защиту от повторов, а `error` и короткое `ended` оставляют балл реакции без изменений.

1. Из оставшихся кандидатов исключаются до пяти последних уникальных доступных треков по `started`, максимум размер доступного каталога минус один. При равной метке времени действует порядок записи в истории. Внутри подборки выбранный трек добавляется в окно недавних. Когда в подборке остаются только недавние треки, возвращается самый давний из них.
2. Если в полученном наборе есть альтернатива предыдущему известному исполнителю, выбираем из альтернатив. Композиции без тега остаются кандидатами. Разнообразие по этому правилу зависит от состава доступного каталога.
3. При равных баллах действует порядок после перемешивания. На каждой позиции алгоритм с вероятностью выбранного режима ищет в полученном наборе лучший ещё не слышанный трек. Когда поиск пропущен или такого трека нет, выбирается кандидат с максимальным баллом.

История считывается целиком, доступность проверяется при каждом запросе. Эту стоимость следует измерять отдельно от ранжирования на больших библиотеках. Веса и размеры окон эвристические. При малом каталоге и строгой защите от повторов у лайков и пропусков меньше возможностей изменить порядок.

## Режимы

| Режим | Вероятность выбора лучшего трека без `started` в истории | Поведение |
| --- | ---: | --- |
| **Знакомое** (`familiar`) | 0% | Выбор по итоговому баллу, включая сигналы предпочтений и истории. |
| **Баланс** (`balance`) | 20% | Поведение 0.1.1. Этот режим используется по умолчанию в новом и обновлённом профилях и при отсутствии `mode` в контексте. |
| **Открытия** (`discovery`) | 80% | При наличии подходящих кандидатов ещё не слышанные треки чаще появляются раньше в очереди. |

Переключатель режима в разделе **Моя волна** сохраняет выбор в SQLite. Следующий расчёт очереди использует новый выбор. Во всех режимах действуют те же веса, защита от повторов и разнообразие исполнителей. Проценты задают вероятность выбора в отдельной позиции при наличии подходящего трека. Фактическая доля новых композиций зависит от каталога, истории и длины очереди. В каталоге из одного доступного трека результат всех режимов совпадает.
