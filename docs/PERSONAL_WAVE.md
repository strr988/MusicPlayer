# Моя волна

Кнопка **Моя волна** запускает радио из локальной библиотеки. Плеер использует первый подходящий Track ID из обновлённой очереди после нажатия **Следующий трек** или естественного окончания. Ручной выбор композиции в таблице возвращает последовательный режим. Кнопка предыдущего трека доступна в последовательном режиме.

При пустой библиотеке запуск доступен после импорта. Если в библиотеке остались только недоступные файлы, плеер сообщает об этом. При единственном доступном треке «Волна» останавливается после окончания или команды перехода. Кнопка запуска позволяет прослушать его снова. При двух треках автоматический переход чередует их. Утрата доступа между расчётом и открытием файла отображается как ошибка воспроизведения. Следующая команда перехода пересчитает доступность.

## Данные и воспроизводимость

`src/recommendations/engine.ts` принимает `RecommendationContext` и максимальный размер очереди. Контекст включает каталог с `id`, `artist`, `genres`, `available`, снимок `ListeningDataReader.getListeningData()`, `now` в миллисекундах Unix и целочисленный 32-битный `seed`. Результат содержит упорядоченные уникальные Track ID. Длина ограничена числом доступных треков. Сортировка ID перед перемешиванием и генератор Mulberry32 дают воспроизводимый результат при фиксированном снимке, времени и seed.

Main проверяет источники штатным механизмом библиотеки и передаёт снимок алгоритму. Метод Preload `getWaveQueue()` возвращает до десяти ID. Main проверяет окно, главный кадр, URL и отсутствие аргументов. Плеер ждёт завершения записи предыдущей сессии перед запросом, поэтому лайки и новые события влияют на ближайший пересчёт. Main выдаёт новый seed при каждом запросе. При перезапуске очередь формируется заново из сохранённых лайков и истории. [Правила записи событий](LISTENING_FEEDBACK.md).

## Формула ранжирования

Для каждого доступного трека вычисляется сумма.

| Признак | Баллы |
| --- | ---: |
| Трек отмечен лайком | +6 |
| Исполнитель совпадает с исполнителем хотя бы одного лайкнутого трека | +2 |
| Хотя бы один жанр совпадает с жанром лайкнутого трека | +1 |
| В истории отсутствует `started` для трека | +1 |
| Каждое `completed` за последние 30 суток, максимум два | +1 |
| Каждый `skipped` за последние 30 суток, максимум два | −4 |

Лайк на треке создаёт сигналы об исполнителе и жанрах. Учитываются и лайки недоступных треков, чьи теги сохранились в каталоге. Отменённый лайк снимает вклад соответствующего трека. Пробелы по краям и регистр тегов игнорируются. Пустые значения пропускаются. При паузе запись пропуска отсутствует. `started` влияет на новизну и защиту от повторов, а `error` и короткое `ended` оставляют балл реакции без изменений.

1. Из оставшихся кандидатов исключаются до пяти последних уникальных доступных треков по `started`, максимум размер доступного каталога минус один. При равной метке времени действует порядок записи в истории. Внутри подборки выбранный трек добавляется в окно недавних. Когда в подборке остаются только недавние треки, возвращается самый давний из них.
2. Если в полученном наборе есть альтернатива предыдущему известному исполнителю, выбираем из альтернатив. Композиции без тега остаются кандидатами. Разнообразие по этому правилу зависит от состава доступного каталога.
3. При равных баллах действует порядок после перемешивания. С вероятностью 20% выбирается лучший ещё не слышанный трек из того же набора, если такой есть. В остальных случаях выбирается кандидат с максимальным баллом.

История считывается целиком, доступность проверяется при каждом запросе. Эту стоимость следует измерять отдельно от ранжирования на больших библиотеках. Веса и размеры окон эвристические. При малом каталоге и строгой защите от повторов у лайков и пропусков меньше возможностей изменить порядок.

## Сравнение алгоритмов

- **A. Случайная очередь** перемешивает доступные уникальные ID с фиксированным seed.
- **B. Очередь по предпочтениям** сортирует по трём признакам лайка из таблицы. Равные баллы разрешаются перемешиванием с тем же seed.
- **C. Моя волна** добавляет историю, разнообразие исполнителей, защиту от повторов и исследование каталога.

Запуск с синтетическим примером или заранее зафиксированным JSON-снимком формата `RecommendationContext` и длиной очереди.

```powershell
node scripts/compare-recommendations.mjs
node scripts/compare-recommendations.mjs snapshot.json 8
```

Для каждого метода скрипт выдаёт ID, число уникальных известных исполнителей и их долю среди треков с известным исполнителем. Также измеряются доля соседних пар одного известного исполнителя среди пар с двумя известными исполнителями, повторы ID внутри списка и совпадения с пятью последними доступными треками из истории. При отсутствии нужных тегов доля возвращается как `null`. В одном списке все три метода выбирают без возвращения, поэтому повторы внутри него равны нулю. Для измерения повторяемости радио следует анализировать объединённую последовательность нескольких пересчётов. Медиана и 95-й перцентиль времени рассчитываются по 100 запускам после 20 прогревочных. Замеры охватывают чистый алгоритм и исключают импорт, SQLite, IPC и декодирование.

Вывод помечен `kind: algorithm-benchmark`. Поле `input` указывает на встроенный синтетический пример или переданный снимок. Метрики очереди описывают состав списка и стоимость расчёта. Оценка попадания во вкус собирается у участников пилота.

## Экспорт результатов пилота

Сохраните фактические результаты завершивших все три условия участников в локальный UTF-8 JSON. Верхний уровень — массив записей. У каждой записи есть уникальный псевдоним `code` и три массива `A`, `B`, `C` по числу запланированных позиций. Элемент массива содержит целую оценку `rating` от 1 до 5, флаг явного пропуска `skipped` и флаг нового лайка `newLike`. Используйте `null` на позициях без оценки из-за технического сбоя или прерывания. Храните причины исключения в локальном журнале. Каждое условие у включённого участника должно содержать хотя бы одну оценённую позицию.

```powershell
node scripts/export-pilot-results.mjs pilot-input.json pilot-aggregate.json
```

Экспорт сначала рассчитывает среднюю оценку и доли явных пропусков и новых лайков среди оценённых позиций каждого участника. Затем он усредняет эти значения с одинаковым весом участников, считает оценённые и исключённые позиции, средние парные разницы C−A и C−B и их выборочное стандартное отклонение. При одном участнике разброс указан как `null`. Размер выборки указан в `participants`. Доли выражены числами от 0 до 1.

Выход содержит только агрегаты по методам. Сохраняйте входные записи локально. Для презентации используйте выходной файл с `kind: pilot-aggregates`. Скрипт требует реальные входные записи и создаёт новый файл. Существующий файл с таким именем вызовет ошибку.
