# Технический аудит

11 ноября 2026 года · Windows · первая сборка 0.1

## Стек и совместимость

Сохраняем Electron, React, TypeScript, electron-vite, Tailwind CSS, music-metadata, HTMLAudioElement и Vitest. SQLite запланирован на шаг сохранения библиотеки. Точные версии и транзитивные зависимости зафиксированы в `package.json` и `pnpm-lock.yaml`.

## Electron и Tauri 2

| Критерий | Electron | Tauri 2 |
| --- | --- | --- |
| Инструменты команды | TypeScript от UI до диалогов, парсера и потоков. | React и TypeScript остаются в UI. Привилегированный код переносится в Rust или требует отдельного процесса для Node-библиотек. На Windows для разработки нужны Rust и MSVC. |
| Установка и кодеки | Дистрибутив содержит Chromium и Node.js, поэтому он крупнее. Версия декодера соответствует сборке. | Обычно меньший пакет с системным WebView2. Версия WebView2 зависит от машины. Нужно отдельно проверить MP3, FLAC, seek и офлайн-установку на целевых машинах. |
| Граница доступа | Sandboxed Renderer, узкий Preload, проверка IPC и локальный протокол. | Capabilities и scopes ограничивают команды и ресурсы окна. Понадобится спроектировать выдачу медиа и ограничения доступа для локальной библиотеки. |

Оставляем Electron для 17 ноября. Команда использует один язык и проверяет поведение аудио на одном зафиксированном Chromium. Пересмотр платформы имеет смысл после релиза при измеримом ограничении размера, памяти или обновления. В таком случае переносим DTO, React и алгоритм рекомендаций. Файловый импорт и выдачу медиа проверяем заново. [Electron](https://www.electronjs.org/docs/latest/tutorial/security), [требования Tauri](https://v2.tauri.app/start/prerequisites/), [WebView](https://v2.tauri.app/reference/webview-versions/), [capabilities](https://v2.tauri.app/security/capabilities/)

## Модули и контракты

| Каталог | Ответственность |
| --- | --- |
| `src/main` | Electron Shell, диалог, `Library`, авторизация и потоковая выдача медиа. Хранилище с миграциями добавляется здесь. |
| `src/preload` | Ограниченный мост `window.musicPlayer`. |
| `src/shared` | DTO, имена каналов и тип `MusicPlayerApi`. Зависимостей от Electron, React и Node.js нет. |
| `src/renderer` | Библиотека и управление одним `HTMLAudioElement`. Очередь первой сборки следует порядку библиотеки. |
| `tests` | Модульные проверки и запуск собранного приложения с синтетическими треками. |

Текущие операции `importFolder()`, `getTracks()` и `getPlayableSource(trackId)` описаны в `src/shared/contracts.ts`. Импорт аддитивный и рекурсивный. Повторный импорт того же канонического пути обновляет метаданные с сохранением ID трека в пределах запуска. Результат различает завершение, отмену и отказ. Неудача отдельного файла сохраняет результаты других. `getPlayableSource` возвращает URL с отдельным случайным ID источника. Доступность файла проверяется при выдаче URL и при открытии потока. После повторного импорта изменённый файл получает новый URL, чтобы Chromium не воспроизводил старые данные из памяти. `Track` передаётся в Renderer без абсолютного пути.

В Electron используются отдельная сессия, CSP, запрет разрешений, скачиваний, навигации и новых окон. Main проверяет `webContents`, главный кадр и URL отправителя. Production Renderer загружается с `music-player://app/`, выдаются только известные ресурсы сборки и импортированные источники. Дев-сервер слушает loopback. Граница защищает от произвольного доступа из Renderer и обнаруживает обычную подмену файла. Файл на диске остаётся изменяемым внешними процессами после открытия. Если модель угроз будет включать активную гонку подмены во время разбора тегов, нужно разбирать метаданные через предварительно проверенный файловый дескриптор.

### Модель для SQLite

| Сущность | Предлагаемые ограничения |
| --- | --- |
| `Track` | UUID, название, nullable исполнитель/альбом/длительность, жанры, ссылка на обложку при появлении поддержки. Длительность хранится в секундах. |
| `SourceItem` | UUID, FK на `Track`, тип источника, локальный канонический путь или ID провайдера, доступность, параметры проверки файла. Уникальные ключи по локальному пути и по паре «провайдер, внешний ID». Пути остаются в Main. |
| `TrackPreference` | Один ряд на `trackId`, `liked`, время изменения. |
| `PlaybackEvent` | ID события и сессии, `trackId`, причина, прослушанные секунды, время UTC. Уникальный ключ терминального события на сессию для защиты от дублей. |
| `Playlist` / `PlaylistItem` | Отдельные таблицы после P0. FK на плейлист и трек, уникальная позиция в плейлисте. |

Сохранение трека и источника выполнять одной транзакцией. Хранить БД в `app.getPath('userData')`, включать внешние ключи и версионировать схему миграциями. После рестарта повторно проверять доступность файлов. Стабильность ID при переименовании файла требует отдельного решения. `MusicWork` и настройки разнообразия добавлять вместе со сценариями, которые их используют.

Следующие контракты обсуждаются вместе с соответствующими функциями. `recordPlaybackEvent(event)` и `setTrackPreference(trackId, liked)` сохраняют факты в Main. `generateWave(context, count)` получает только кандидатов, предпочтения и историю, возвращает `TrackId[]`. Для воспроизводимых сравнений контекст передаёт время и seed. Тесты алгоритма не требуют Electron и базы данных.
