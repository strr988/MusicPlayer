# React Renderer Music Player

- Соблюдай границы из корневого `AGENTS.md`. Для данных библиотеки используй типизированный Preload API. Сохраняй один `HTMLAudioElement` и офлайн-работу.
- Вычисляй значения из текущих props и state при рендере. Синхронизируйся с внешними системами в эффектах, а действия пользователя обрабатывай в обработчиках. Для асинхронной загрузки учитывай смену запроса, ошибки и устаревшие ответы.
- Проследи путь частых событий до потребителей состояния. Если профилирование покажет, что обновление позиции заметно нагружает библиотеку, сузь область обновлений. Используй стабильные ID в списках и добавляй мемоизацию при измеримой пользе.
- Рекомендации о Next.js, SSR, RSC и серверном кэше находятся за пределами этого Renderer. При ревью связывай каждое замечание с конкретным кодом и сценарием. Изменения ограничивай задачей.

Проектная адаптация [руководства Vercel](https://github.com/vercel-labs/agent-skills/blob/805687f34e8c10b420e3d11335a0ca2c3c90d992/skills/react-best-practices/SKILL.md). Для эффектов сверяйся с [документацией React](https://react.dev/learn/synchronizing-with-effects).
