# Работа над mustplay

- Перед изменениями прочитай `docs/PROJECT_SPEC.md`, `docs/TECHNICAL_AUDIT.md` и `docs/MVP_PLAN.md`. Для первой сборки приоритет имеет объём, заданный пользователем. Согласовывай смену стека и расширение объёма конференционного MVP с командой.
- Работай в отдельной ветке. Делай минимальные изолированные изменения в рамках задачи и сохраняй чужие правки. Согласовывай изменения утверждённой архитектуры. Выполняй push и merge только по прямому разрешению пользователя.
- Держи зависимости направленными к общим DTO в `src/shared`. Файлы, диалоги и будущее хранилище принадлежат Main. Renderer работает через типизированный API Preload и управляет одним `HTMLAudioElement`. Рекомендации должны принимать обычные данные и возвращать ID без зависимости от Electron, React и SQLite.
- Для новых IPC-операций проверяй отправителя, кадр и входные значения на стороне Main. Добавляй только именованные методы. Сохраняй sandbox, context isolation, CSP и запрет Node.js в Renderer. Локальные пути, произвольные каналы IPC и универсальные файловые операции остаются внутри Main. При изменении границ доступа сверяйся с [чек-листом безопасности Electron](https://www.electronjs.org/docs/latest/tutorial/security).
- Читай пользовательские аудиофайлы без изменения оригиналов. Выдавай медиаданные только по ID импортированного источника. Тестируй повреждённые файлы, повторный импорт и потерю доступа к источнику. Используй синтетические или явно разрешённые аудиофайлы.
- Добавляй функциональность сквозными сценариями. Избегай пустых экранов и команд для ещё отсутствующих возможностей. Меняй общие контракты вместе с их вызовами и проверками. Записывай значимые решения и ограничения в документации.
- Используй зафиксированный `pnpm-lock.yaml`. При изменении зависимостей проверяй требования к Node.js, совместимость с Electron и запуск Windows-сборки. Перед передачей работы запускай `pnpm build`, `pnpm test` и для изменений в импорте, IPC или плеере `pnpm test:desktop`. Сообщай об успехе только по фактическим результатам проверок текущего состояния. Указывай ошибки, пропущенные проверки и их причины.
- Применяй навыки из `.agents/skills` в пределах задания и правил репозитория. `vercel-react-best-practices` предназначен для изменений и ревью React Renderer, `verification-before-completion` — для итоговой проверки.
